# 国外VPS：从机房、线路到价格，2026年怎么选才不容易买错

搜索“国外VPS”，真正让人纠结的通常不是“哪家名气大”，而是三个更现实的问题：**服务器放哪里、回程线路是什么、同样的钱到底能买到多少资源**。

尤其是面向中国大陆用户时，洛杉矶、日本、香港看起来都是“海外节点”，实际访问体验却可能完全不同。即使同一个城市，Premium、Eyeball、Tier 1 三种网络也可能对应不同的线路策略和价格。

这也是为什么选国外VPS时，单看“1核2G”“10Gbps”这些参数很容易买偏。真正需要对比的是机房、线路、流量口径、带宽限制、库存状态，以及退款规则。

这篇文章以当前公开资料为基础，把国外VPS的选型逻辑、DMIT当前可见套餐、价格差异和使用限制放在一起讲清楚。下面价格均以官方页面当前公开美元价格为准，但官方也明确提醒价格可能因调整出现更新滞后。

## 国外VPS到底该看什么

如果用途只是搭一个海外测试环境，CPU和内存当然重要；但如果用户主要来自中国大陆，那么**线路往往比多出来的1核CPU更值得关注**。

DMIT目前公开的 Cloud Instance 产品采用 KVM 虚拟化，并提供 Los Angeles、Hong Kong、Tokyo 三个主要节点。官方把网络分成 Premium、Eyeball 和 Tier 1 三个系列：Premium 强调中国大陆方向的优化，并使用 China Telecom CN2 GIA；Eyeball 使用 CMI 等面向终端用户的中国网络方向；Tier 1 则更偏向普通国际互联，不针对中国大陆访问做专门优化。

这三类线路对应的使用场景其实很直白。

**Premium** 更适合跨境网站、面向中国大陆用户的应用、对延迟比较敏感的业务。官方给出的香港参考数据是香港到深圳约 15ms，并以 0.1% 峰值丢包作为展示口径；东京方向官方给出的参考值约 30ms，但实际延迟会受到接入网络、路由和时间影响。

**Eyeball** 更像中间档。它不是 Premium 那种中国大陆专门优化的高价线路，但又不是完全不管中国访问的普通 Tier 1。官方将其定位在全球用户与中国用户混合访问的网站、API、SaaS、远程开发等场景。

**Tier 1** 则更适合国际业务、备份、CI/CD、监控、开发测试等不太依赖中国大陆方向优化的用途。官方明确把它描述成成本更友好的系列。

这一区分非常重要：**“国外VPS便宜”与“回国线路便宜”不是一回事。**

## 美国、香港、日本，国外VPS怎么选

### 洛杉矶：兼顾北美与亚洲的常见落点

DMIT把洛杉矶定位为其北美旗舰节点，当前官网描述中包括 CoreSite 和 Digital Realty 的部署，并强调其 Pacific Rim 互联位置与较大的网络容量。

对于美国用户、北美业务、跨太平洋业务，洛杉矶自然是一个比较容易理解的选择。中国大陆用户也经常关注 LAX，因为美国西海岸到亚洲的网络路径通常比美国东海岸更符合跨太平洋业务场景。

需要注意的是，**洛杉矶 Premium、Eyeball、Tier 1 不能当成三个“换个名字的套餐”**。它们的网络策略不同，价格也不同。

例如当前官方公开的 LAX.AN5.T1 Volume，从 V2C2G 的 $14.90/月，到 V12C24G 的 $199.90/月；同一页的 General 系列则从 $16.90/月起。

### 香港：延迟低，但价格和线路要分开看

香港节点是很多中国用户搜索国外VPS时首先想到的地区，原因很简单：地理距离近。

DMIT 当前官方资料把香港节点放在 Equinix HK2，并给出约 15ms 到深圳的参考延迟。与此同时，香港 Eyeball 目前仍被标为 Beta，官方明确提醒其产品和网络路由仍在调优，不建议把它直接当成高稳定生产环境。

因此，看到“HKG”“低延迟”还不够。真正应该继续看的是 Premium、Eyeball 还是 Tier 1。

### 东京：东亚方向更自然的选择

东京节点针对日本、韩国以及更广泛的东亚访问场景。DMIT 官方资料给出的东京到中国大陆参考延迟约 30ms，并将其描述为靠近主要海缆系统的东亚节点。

如果网站主要服务日本、韩国、东亚用户，东京比单纯追求“美国价格”更容易解释得通。反过来，如果你的用户大多在北美，东京的优势就没有那么明显。

## 为什么同样是 4 核 4GB，价格能差这么多

看表时不要被“4 vCore + 4GB RAM”骗到。

以当前公开套餐为例，LAX AN5 系列里，4 核 4GB 的 Pro MINI 是 $79.90/月，Eyeball MINI 也是 $79.90/月；但 LAX AN5 T1 Volume 的 V4C4G 只有 $36.90/月。区别主要不在 CPU 或内存，而是在**网络系列和流量设计**。

另外，同样叫 MINI，不同区域也不代表同一个产品。例如 HKG AS3 Pro MINI 是 2 核 4GB、60GB SSD、1.5TB 流量，$126.90/月；TYO AS3 Pro MINI 同样是 2 核 4GB、60GB SSD，但流量为 2TB，价格 $89.90/月。

所以看国外VPS时，套餐名称本身没有多大可比性。**产品 ID、地区、线路和流量口径才是有效比较单位。**

## T1 为什么看起来特别便宜

DMIT 当前 Tier 1 系列里，确实存在非常低的公开价格。

LAX AS3 T1 的 TINY 是 **$6.90/月**，LAX AS3 T1 的 WEE 甚至展示为 **$36.90/年**；HKG 和 TYO 的 AS3 T1 STARTER、MINI、MICRO 也分别从 $12.90、$21.90、$32.90/月起。

但便宜的原因不是“同规格突然打了大折扣”，而是产品定位不同。Tier 1 系列主要针对国际互联、开发、备份、监控和对中国大陆专门路由没有硬要求的场景。

另外，LAX AS3 还有一个当前需要直接写在采购清单上的限制：官方提示该系列仍在建设和优化阶段，在此期间可能出现**较低的磁盘性能和较低的 SLA**。

也就是说，拿 $6.90 的 TINY 和 $79.90 的 Premium 产品做简单的“价格/核心数”除法，意义不大。

## Premium、Eyeball、Tier 1，实际应该怎么判断

可以把选择逻辑压缩成一句话：

**中国大陆访问体验优先，看 Premium；中国与全球混合业务、希望压低成本，看 Eyeball；主要面向海外用户或国际网络，优先看 Tier 1。**

这不是对某个系列做高低排名，而是 DMIT 官方自己给出的产品定位差异。Premium 当前明确使用 CN2 GIA；Eyeball 使用 CMI 等中国方向网络；Tier 1 则不针对中国大陆做专门线路增强。

如果你的业务是中国大陆访客较多的网站，那么先决定“回国线路”，再决定 CPU/RAM，会比反过来更省时间。

如果是海外博客、Git 服务、监控节点、备份服务器，则没必要因为“CN2 GIA”四个字就主动支付溢价。

## DMIT 的硬件现在是什么水平

DMIT 当前公开的硬件平台包括 AN5、AN4 和 AS3。

官方资料显示，AN5 使用 AMD EPYC 9005 系列，也就是 Zen 5；AN4 使用 AMD EPYC 9004 系列、Zen 4；AS3 使用 AMD EPYC 7003 系列、Zen 3。官方同时把 AN5 定位为最高性能平台、AN4 作为相对均衡的成熟平台、AS3 作为更强调价格的系列。

当前 LAX AN5 T1 的公开配置里也能看到很明显的差别：

V2C2G 是 2 核、2GB、40GB SSD、5TB Max、10Gbps，$14.90/月；

V4C8G 是 4 核、8GB、160GB SSD、40TB Max、10Gbps，$52.90/月；

V12C24G 则已经来到 12 核、24GB、320GB SSD、160TB Max、10Gbps，$199.90/月。

这说明它的产品梯度并不是单纯“加内存”，而是同时提高核心、磁盘和流量配额。

## “10Gbps”不等于每台机器都有10Gbps持续下载

这一点尤其值得注意。

官方把网络端口速率列成 10Gbps、4Gbps、2Gbps、1Gbps 等，但同时注明带宽数字代表理想情况下的最大值，实际可能受到网络运行状况、虚拟机性能和其他网络环境影响。

因此：

**10Gbps 是接口能力，不应该直接理解成全天候稳定的10Gbps互联网吞吐。**

对于 VPS 购买，真正值得比较的是“端口上限 + 流量配额 + 流量计费方式 + 路由类型”。

这也是为什么 T1 Volume 的产品描述里使用了 `Max (IN, OUT)`，而其他套餐又使用固定月度流量配额。两个数字看起来都很大，实际口径并不完全一样。

## 退款规则比优惠码更值得看

优惠码当然让人开心，但买国外VPS前，退款政策其实更加重要。

DMIT 当前服务条款写得比较明确：新订单在购买不超过 **3天**、且虚拟机流量使用不超过 **30GB** 的条件下，可申请全额退款，但会扣除支付网关收取的交易费用。新订单在购买不超过 **30天** 的情况下，还存在部分退款规则。续费订单、已经用账户余额支付的订单，以及部分特殊情况则属于不可退款范围。

还有一些容易被忽略的条件。条款明确说明，因 IP 地理位置、网络表现不符合预期、DDoS 等情况，并不自动构成退款理由。

因此，第一次购买某个线路时，比较稳妥的思路不是一上来就预付很长周期，而是先确认线路、IP 和业务场景，再决定是否长期使用。
